# تسبیحات حضرت زهرا (Android)

یک اپلیکیشن اندرویدی ساده، آرام و آفلاین بر اساس مشخصات ارائه‌شده. کاربر با لمس صفحه در سه مرحله (الله اکبر / الحمدلله / سبحان الله) پیش می‌رود و در پایان به یک تصویر نهایی می‌رسد.

این پروژه با **تصاویر و صداهای نمونه (placeholder)** ساخته شده تا بلافاصله قابل build و تست باشد. تصاویر نمونه فقط رنگ زمینه + شماره تصویر را نشان می‌دهند و صداهای نمونه صرفاً تن‌های ساده هستند — همه باید با فایل‌های واقعی جایگزین شوند.

---

## ۱. فایل‌های مهم پروژه کجاست؟

```
TasbihatZahra/
├── app/
│   ├── build.gradle.kts                 # تنظیمات build ماژول (compileSdk/targetSdk 36, minSdk 23, ...)
│   └── src/main/
│       ├── AndroidManifest.xml
│       ├── assets/
│       │   ├── images/                  # همه‌ی تصاویر برنامه (بخش ۲)
│       │   └── audio/                   # همه‌ی فایل‌های صوتی برنامه (بخش ۳)
│       ├── java/ir/zahra/tasbihat/
│       │   ├── MainActivity.kt          # نقطه ورود، چرخه حیات صدا، Intent بازخورد
│       │   ├── data/
│       │   │   ├── Content.kt           # تعریف مراحل: تعداد تصاویر، متن ذکر، مسیر صدا
│       │   │   ├── SettingsStore.kt     # ذخیره‌سازی وضعیت روشن/خاموش موسیقی و ذکر
│       │   │   └── AssetImageLoader.kt  # بارگذاری بهینه تصاویر از assets
│       │   ├── audio/AudioController.kt # دو کانال مستقل: موسیقی پس‌زمینه + صدای ذکر
│       │   └── ui/
│       │       ├── TasbihatState.kt     # ماشین‌حالت اصلی برنامه (splash → مرحله ۱،۲،۳ → پایانی)
│       │       ├── TasbihatApp.kt       # صفحات و انیمیشن‌های Slide/Fade
│       │       └── components/          # نوار پایین، نقاط پیشرفت، پنل تنظیمات، ...
│       └── res/                         # آیکون، رنگ‌ها، متن‌های ثابت (strings.xml)
├── .github/workflows/build-apk.yml      # ساخت خودکار APK با GitHub Actions (بخش ۵)
└── gradle/libs.versions.toml            # نسخه‌های وابستگی‌ها
```

## ۲. تصاویر واقعی را دقیقاً کجا قرار دهم؟

مسیر: `app/src/main/assets/images/`

| مرحله | پوشه | نام فایل‌ها |
|---|---|---|
| تصویر ابتدایی (Splash) | `images/` | `splash.jpg` |
| مرحله ۱ (الله اکبر) | `images/section1/` | `section1_01.jpg` تا `section1_34.jpg` |
| مرحله ۲ (الحمدلله) | `images/section2/` | `section2_01.jpg` تا `section2_33.jpg` |
| مرحله ۳ (سبحان الله) | `images/section3/` | `section3_01.jpg` تا `section3_33.jpg` |
| تصویر نهایی | `images/` | `final_image.jpg` |

فقط کافی است فایل نمونه را با فایل واقعی خودتان **با همین نام دقیق** جایگزین کنید — نیازی به تغییر کد نیست. ابعاد پیشنهادی: ۱۹۲۰×۱۰۸۰ (یا هر نسبتی، چون تصویر با `Crop` به‌صورت خودکار در صفحه عمودی بزرگ‌نمایی می‌شود).

اگر در آینده تعداد تصاویر یک مرحله را تغییر دادید (مثلاً ۳۴ عدد شد ۴۰ عدد)، فقط عدد `imageCount` مربوط به همان مرحله را در فایل `app/src/main/java/ir/zahra/tasbihat/data/Content.kt` تغییر دهید.

## ۳. فایل‌های صوتی واقعی را کجا قرار دهم؟

مسیر: `app/src/main/assets/audio/`

| فایل | نقش |
|---|---|
| `audio1.wav` | صدای ذکر «الله اکبر» (برای هر تصویر مرحله ۱ از اول پخش می‌شود) |
| `audio2.wav` | صدای ذکر «الحمدلله» |
| `audio3.wav` | صدای ذکر «سبحان الله» |
| `audio4.wav` | موسیقی پس‌زمینه دائمی (Loop) |

می‌توانید فرمت را به `.mp3` هم تغییر دهید؛ کافی است پسوند فایل در `Content.kt` (مقدار `audioAssetPath`) و در `AppContent.BACKGROUND_MUSIC_ASSET` هماهنگ باشد.

## ۴. در آینده چطور فقط تصاویر/صداها را جایگزین کنم؟

1. فایل جدید را با **همان نام** به‌جای فایل نمونه در `assets/images/...` یا `assets/audio/...` کپی کنید.
2. اگر فقط محتوای هنری عوض شده (نه تعداد تصاویر یا نام فایل‌ها)، هیچ تغییر کدی لازم نیست.
3. پروژه را دوباره Build بگیرید.

منطق برنامه کاملاً از محتوا جدا شده (تمام تنظیمات در `Content.kt`)، پس تعویض هنر هیچ‌وقت به تغییر منطق نیاز ندارد.

## ۵. چطور با GitHub یک APK بسازم؟

این پروژه یک workflow آماده در مسیر `.github/workflows/build-apk.yml` دارد:

1. یک ریپازیتوری جدید در GitHub بسازید و کل این پوشه را push کنید.
2. به تب **Actions** بروید؛ workflow با نام «Build debug APK» به‌صورت خودکار روی هر push اجرا می‌شود (یا می‌توانید دستی از دکمه Run workflow اجرا کنید).
3. بعد از پایان اجرا، از بخش **Artifacts** فایل `tasbihat-zahra-debug-apk` را دانلود کنید — یک APK قابل نصب (نسخه debug) است.

برای build محلی در Android Studio (نسخه‌ی هم‌خوان با ۲۰۲۶.۱.۳): پروژه را باز کنید؛ چون فایل `gradle-wrapper.jar` در ریپو قرار نگرفته (باینری است)، Android Studio به‌محض Sync آن را خودش می‌سازد، یا می‌توانید دستی با یک نصب Gradle موجود دستور زیر را اجرا کنید:

```
gradle wrapper --gradle-version 9.5.0
./gradlew assembleDebug
```

## نکات فنی

- برنامه کاملاً آفلاین است: هیچ دسترسی اینترنت، دیتابیس، حساب کاربری یا سرویس گوگل استفاده نشده.
- جهت صفحه فقط Portrait است (`android:screenOrientation="portrait"`).
- موسیقی پس‌زمینه (`audio4`) و صدای ذکر دو کانال کاملاً مستقل هستند (`AudioController.kt`) و وضعیت روشن/خاموش هرکدام در `SharedPreferences` ذخیره و در باز کردن بعدی بازیابی می‌شود.
- انتقال بین تصاویر: Slide افقی + مقدار کمی Fade (`TasbihatApp.kt`). انتقال از Splash به مرحله اول: صرفاً Fade، طبق مشخصات.
- ایمیل بازخورد به آدرس نمونه‌ی `feedback@example.com` در `res/values/strings.xml` (`feedback_email_address`) تنظیم شده — آن را به ایمیل واقعی خودتان تغییر دهید.
- آیکون برنامه (Adaptive Icon + نسخه‌ی legacy برای Android 6–7) به‌صورت یک نماد ساده‌ی دانه‌های تسبیح ساخته شده و در `res/drawable/ic_launcher_*.xml` قابل ویرایش است.
